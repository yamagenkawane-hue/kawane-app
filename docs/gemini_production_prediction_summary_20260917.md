# Gemini APIによる生産予測の確定仕様

作成日: 2026-09-17

最終更新日: 2026-09-18

本書の第8節以降が最新の確定仕様である。第2～7節は初期検討記録として保持し、相違がある場合は最新仕様を優先する。API連携・定期更新・DB追加・画面変更は未実装である。

## 1. 現在の状態

現在のAI予測機能は、工程能力・実績平均・休日・遅延補正による計算式であり、外部AIは使用していない。今後、Google Gemini APIを利用する。API連携・定期更新・予測用テーブルは未実装である。

## 2. 確定事項

| 項目 | 内容 |
| --- | --- |
| 使用するAI | Google Gemini API |
| 予測対象 | 製造・洗浄・検査・計量・梱包・外注など全工程 |
| 更新日時 | 毎朝9:00、日本時間で1回 |
| 登録・変更時の更新 | 実績登録・数量編集・工程移動・外注日程変更・生産予定変更時には再予測しない |
| 画面表示 | 最後に保存された予測結果を表示する |
| 過去実績の扱い | 過去実績の反映が有効で対象工程の実績がある場合、設定日産数量と比較せず過去実績を使用する |

以前検討した登録・変更時の自動再予測は取り下げ、当面は毎朝9:00のみとする。

## 3. 予測に使用するデータ案

| データ | 用途 |
| --- | --- |
| 受注情報 | 製品・受注数量・納期・出荷済数量から必要生産量を把握 |
| ロット別工程数量 | 現在工程・数量・完了状態を把握 |
| 製造実績 | 登録日・生産数量から実績日産数量を把握 |
| 工程移動履歴 | ロットの工程通過日数を把握 |
| 製品工程マスタ | 工程順・重複日数を把握 |
| 工程能力設定 | 実績が不足する工程の能力情報を補足 |
| 外注管理 | 出し日・戻り予定日・戻り実績日を反映 |
| デイリー生産予定 | 計画数・プレス機No・部署別完了予定日を反映 |
| 会社カレンダー | 休日を反映 |
| 他の未完了受注 | 同じ工程・設備への仕事の集中を把握 |

製造以外は実績登録を行わない運用のため、工程移動履歴を中心に使用する。工程間の日数には待ち時間が含まれるため、加工時間とは区別する。

履歴をすべて送信するのではなく、製品・工程別に集計した実績と現在の生産状況を送信する案とする。得意先名・注番など予測に不要な名称は、内部識別IDへの置き換えを検討する。

設備の待ち順・稼働時間などを記録していない場合、混雑による遅延予測は概算となる。

## 4. 処理構成案

1. 毎朝9:00に未完了受注と実績・履歴を取得する。
2. 製品・工程別に実績を集計し、DBに保存する。
3. 集計データと現在の生産状況をGeminiへ送信する。
4. 工程ごとの必要日数・予測理由を決まったJSON形式で受け取る。
5. システム側で回答を検証し、休日・工程順・重複日数を適用する。
6. 完了予測日をDBに保存し、ガントチャートに反映する。

9:00は処理開始時刻とする案であり、全件の予測完了時刻を保証するものではない。呼び出しを順次実行し、利用制限への集中を抑える。

APIが失敗した場合は前回の予測結果を保持する案とする。GeminiへのAPI接続だけで工場専用モデルが自動学習されるわけではない。

## 5. DB保存構成案

元の実績・履歴は保持し、予測用のデータは別に保存する。

| 種類 | 保存内容 |
| --- | --- |
| 実績集計 | 製品・工程別平均日産数量、工程通過日数、集計期間、対象件数 |
| 予測結果 | 工程ごとの必要日数・完了予測日・予測理由・更新日時 |
| 実行履歴 | 使用モデル、成功・失敗、エラー内容 |
| 使用した集計値 | 過去の予測根拠を確認できるよう実行単位で保存 |

テーブル構成・保持期間・詳細な集計方法は未確定である。

## 6. API利用の準備と費用

- Googleアカウント、Google Cloudプロジェクト、Gemini APIキーが必要。
- APIキーはサーバー側の環境変数で管理し、ブラウザーやGitに公開しない。
- 使用モデル、利用上限、料金、社内データの取り扱い条件を確認する。
- 毎朝9:00に実行できるサーバーまたは定期実行サービスが必要。

未完了受注は100件未満との回答があるが、正確な件数は未把握。無料枠に収まるかはモデル・送信量・呼び出し回数によるため、保証しない。架空データで検証し、利用量と予測精度を確認する案とする。無料枠のデータ利用条件と、有料サービスの条件を区別して確認する。

## 8. 利用と更新の確定仕様

- Gemini APIの無料枠と架空のテストデータで検証する。モデルは `gemini-3.8-flash` に固定し、実行履歴に保存する。APIキー取得後に利用可否・上限を確認する。
- Vercel Hobbyで毎朝7:00～7:59（日本時間）に開始する。9時更新の旧案は取り下げる。完了時刻は保証しない。
- 処理開始時点のデータで予測し、その後の変更は翌朝に反映する。登録・変更時の自動更新は行わない。
- 検証中はAI予測設定画面に全対象注番の手動更新ボタンを設け、本番移行時に削除する。
- 手動更新は押した時点のデータ・保存済み条件を使用する。処理中はボタンを無効化し、定期更新との同時実行も防ぐ。
- 最終実行日時、成功・失敗・利用上限による未処理件数の表示は設計で具体化する。

## 9. 対象と完了の定義

- 全工程をロット別に予測し、未製造分も含めて注番ごとの予測を表示する。
- 余剰分も全工程と設備占有に含め、他受注への影響を反映する。注番全体の完了予測日は余剰分を含む最後のロットの完了日。
- 引当数量は必要生産量から差し引く。全量引当であっても進行中ロットがあれば予測対象に含める。
- 必要数量を満たし、余剰分を含む全対象ロットが梱包完了した注番は定期予測から除外する。未製造の必要数量が残る間は完了扱いにしない。
- 精度評価に使う実際の完了日も、余剰分を含む最後の梱包完了日。

## 10. 参照条件と設定画面

AI予測設定画面で以下を全製品・全工程共通の設定として変更可能にする。入力は電卓式。

| 設定 | 初期値 | 制約 |
| --- | --- | --- |
| 優先参照期間 | 90日 | 1以上の整数 |
| 最大参照期間 | 730日 | 優先期間以上 |
| 製造の基準生産日数 | 5日分 | 1以上の整数 |
| その他工程の基準ロット数 | 5ロット分 | 1以上の整数 |

優先期間で不足すれば必要な分だけ遡り、基準を満たした時点までの実績をすべて使用する。同じ日付の実績は分割せず含める。最大期間でも不足すれば実績不足。

- 製品・工程・参照開始日の一覧をAI予測設定画面に設ける。開始日より前は最大期間内でも使用しない。
- 検証中は製品・工程共通。本番はプレス機別・外注先別を追加し、個別開始日を優先する。未設定なら共通開始日、共通も未設定なら参照期間のみを使用する。
- 条件変更は次回の更新で反映する。AI予測ON/OFFの表示切り替えは即時。
- AI予測OFFはGemini・定期更新を停止し従来ガントを表示。履歴は保持する。
- 過去実績OFFはGeminiを呼ばず能力設定で計算。全工程実績不足の場合もGeminiを呼ばず計算結果を保存する。
- 実績が十分な工程だけGeminiで予測し、不足工程の能力計算と工程順に組み合わせる。

既存のAI予測・過去実績チェックは残す。外注遅延・出荷遅延・予測に加える余裕・工程平均遅延の固定加算を廃止する。ライン負荷の固定能力低下も廃止する。稼働率・外注工程・休日・現在の遅れのチェックは廃止し、本書のルールを常に適用する。

## 11. 実績と必要日数

- 製造は製品・工程・プレス機別に数量合計を生産日数で割る。同日・同製品・同機械の複数注番やロットは合算し1日分とする。
- 機械別実績不足時は他機械を混ぜず能力設定を使う。機械未設定の場合だけ製品・工程別実績を使用する。
- 他の社内工程は製品・工程別に、入った日～移動日（梱包は完了日）を会社カレンダーの営業日で集計する。同日処理は1日。待ち時間が含まれる点を区別する。
- 外注は製品・工程・外注先別に、出し日～戻り実績日を暦日で集計する。同日返却は1日。他社の実績は混ぜない。
- 実績十分なら設定日産との比較・稼働率の重ね掛けはしない。実績不足なら不足実績は使わず、日産能力×稼働率で計算する。
- 社内は営業日、外注は暦日で切り上げ、未完了工程は最短1日。完了済みは実際の日付を使用する。
- 能力計算が必要な場合に能力未登録・稼働率0％・同工程の有効設定複数なら予測不能。
- 独立して計算可能な工程は表示するが、一部工程が予測不能なら注番全体も予測不能。
- 未製造分は製造Gの開始予定日を使う。未設定・過去なら更新日以降の最初の営業日を仮定しコメント表示する。
- 休日・工程順・重複日数はシステム側で適用する。生産予定の完了予定日、外注戻り予定日は予測計算に使用しない。

## 12. 設備と外注

- 設備競合は同じプレス機の製造のみ。余剰生産も占有時間に含める。他工程の設備競合は計算しない。
- 同じ注番・機械で実績があり、未製造必要数量または計画数量が残る状態を製造中とする。
- 製造中を優先し最終製造実績日の新しい順、同日なら納期・注番順。未着手は納期・注番順。実際の予定は変更しない。
- プレス機未設定は競合を考慮せずコメント表示。先行製造が予測不能なら同じ機械の後続も予測不能とし、原因の注番を示す。
- 外注返却済みは戻り実績日を確定日として後工程を予測する。未返却は実績所要日数を出し日に加える。不足時は能力設定で求めた暦日数を加える。
- 外注先未設定は予測不能。出し日未登録は前工程完了予測後に出す想定としコメント表示。前工程が予測不能なら外注も予測不能。
- 戻り予測日を超えて未返却の場合は超過コメントを表示し、外注・後工程・注番全体を予測不能とする。戻り実績登録後の次回更新で再予測し、実績も集計に加える。

## 13. 表示・コメント・失敗

- ガントに工程別完了予測日。コメントに理由・最終成功更新日時・不足情報・失敗を表示する。複数コメントは工程名付きで1件ずつ改行し、上書きしない。
- 各工程に「Geminiによる実績予測」または「工程能力設定による計算」を表示する。
- 注番ごとに完了予定日・AI完了予測日・営業日差を表示し、遅い予測は赤字。
- 比較元は各ロットの梱包出荷G完了予定日の最も遅い日。一部未登録なら差は「－」。未製造分は注番単位の梱包出荷G完了予定日を使い、なければ「－」。
- 一部注番失敗時も成功分は更新する。失敗分は前回結果を保持し、なければ「予測未取得」。最終成功日時は変更しない。
- 通信エラー・一時障害・不正回答は当日再試行せず翌朝実行する。API上限は当日のGemini呼び出しを停止し、未処理分は前回結果を保持する。

確定コメント:

- 「実績不足のため、工程能力設定の日産数量で計算しています。」
- 「稼働率が0％のため予測できません。」
- 「工程能力設定に同じ工程の有効な設定が複数登録されているため、予測できません。使用する設定を1件に整理してください。」
- 「プレス機No未設定のため、設備の競合を考慮していません。」
- 「出し日未登録のため、前工程の完了予測日を基準に外注日程を予測しています。」
- 「実績に基づく戻り予測日を超過しています。」
- 「予測の更新に失敗しました。翌朝の定期更新で再実行します。」
- 「API利用上限に達したため、今回の予測は更新できませんでした。翌朝の定期更新で再実行します。」

## 14. 保存・精度評価

- 元の製造実績・移動履歴は保持し、参照期間に従って毎回再集計する。
- 予測結果・使用集計データ・実行記録は90日保存する。ただし最新成功結果は表示用に別途保持する。
- 評価用データは別に保存し、90日後も保持する。未完了受注も評価に必要な日付を残す。
- 注番・予測実行日・AI完了予測日・従来計算の予測日・実際の完了日・営業日誤差を記録する。
- 各予測が完了の何営業日前のものかも評価する。許容誤差は検証後に決定する。

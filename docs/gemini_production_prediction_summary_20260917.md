# Gemini APIによる生産予測の整理

作成日: 2026-09-17

## 1. 現在の状態

現在のAI予測機能は、工程能力・実績平均・休日・遅延補正による計算式であり、外部AIは使用していない。今後、Google Gemini APIを利用する。API連携・定期更新・予測用テーブルは未実装である。

## 2. 確定事項

| 項目 | 内容 |
| --- | --- |
| 使用するAI | Google Gemini API |
| 予測対象 | 製造・洗浄・検査・計量・梱包・外注など全工程 |
| 更新日時 | 毎朝9:00、日本時間で1回 |
| 登録・変更時の更新 | 実績登録・数量編集・工程移動・外注日程変更・生産予定変更時には再予測しない |
| 画面表示 | 最後に保存された予測結果を表示する |
| 過去実績の扱い | 過去実績の反映が有効で対象工程の実績がある場合、設定日産数量と比較せず過去実績を使用する |

以前検討した登録・変更時の自動再予測は取り下げ、当面は毎朝9:00のみとする。

## 3. 予測に使用するデータ案

| データ | 用途 |
| --- | --- |
| 受注情報 | 製品・受注数量・納期・出荷済数量から必要生産量を把握 |
| ロット別工程数量 | 現在工程・数量・完了状態を把握 |
| 製造実績 | 登録日・生産数量から実績日産数量を把握 |
| 工程移動履歴 | ロットの工程通過日数を把握 |
| 製品工程マスタ | 工程順・重複日数を把握 |
| 工程能力設定 | 実績が不足する工程の能力情報を補足 |
| 外注管理 | 出し日・戻り予定日・戻り実績日を反映 |
| デイリー生産予定 | 計画数・プレス機No・部署別完了予定日を反映 |
| 会社カレンダー | 休日を反映 |
| 他の未完了受注 | 同じ工程・設備への仕事の集中を把握 |

製造以外は実績登録を行わない運用のため、工程移動履歴を中心に使用する。工程間の日数には待ち時間が含まれるため、加工時間とは区別する。

履歴をすべて送信するのではなく、製品・工程別に集計した実績と現在の生産状況を送信する案とする。得意先名・注番など予測に不要な名称は、内部識別IDへの置き換えを検討する。

設備の待ち順・稼働時間などを記録していない場合、混雑による遅延予測は概算となる。

## 4. 処理構成案

1. 毎朝9:00に未完了受注と実績・履歴を取得する。
2. 製品・工程別に実績を集計し、DBに保存する。
3. 集計データと現在の生産状況をGeminiへ送信する。
4. 工程ごとの必要日数・予測理由を決まったJSON形式で受け取る。
5. システム側で回答を検証し、休日・工程順・重複日数を適用する。
6. 完了予測日をDBに保存し、ガントチャートに反映する。

9:00は処理開始時刻とする案であり、全件の予測完了時刻を保証するものではない。呼び出しを順次実行し、利用制限への集中を抑える。

APIが失敗した場合は前回の予測結果を保持する案とする。GeminiへのAPI接続だけで工場専用モデルが自動学習されるわけではない。

## 5. DB保存構成案

元の実績・履歴は保持し、予測用のデータは別に保存する。

| 種類 | 保存内容 |
| --- | --- |
| 実績集計 | 製品・工程別平均日産数量、工程通過日数、集計期間、対象件数 |
| 予測結果 | 工程ごとの必要日数・完了予測日・予測理由・更新日時 |
| 実行履歴 | 使用モデル、成功・失敗、エラー内容 |
| 使用した集計値 | 過去の予測根拠を確認できるよう実行単位で保存 |

テーブル構成・保持期間・詳細な集計方法は未確定である。

## 6. API利用の準備と費用

- Googleアカウント、Google Cloudプロジェクト、Gemini APIキーが必要。
- APIキーはサーバー側の環境変数で管理し、ブラウザーやGitに公開しない。
- 使用モデル、利用上限、料金、社内データの取り扱い条件を確認する。
- 毎朝9:00に実行できるサーバーまたは定期実行サービスが必要。

未完了受注は100件未満との回答があるが、正確な件数は未把握。無料枠に収まるかはモデル・送信量・呼び出し回数によるため、保証しない。架空データで検証し、利用量と予測精度を確認する案とする。無料枠のデータ利用条件と、有料サービスの条件を区別して確認する。

## 7. 設計前に確定する事項

- 使用モデル、無料枠または有料枠の選択。
- 実績の集計期間・集計方法・実績不足と判断する基準。
- 実績不足時の工程能力・予定日の使用方法。
- 過去実績採用時に適用するその他の補正。
- 予測結果・理由・更新日時・更新失敗の画面表示方法。
- 定期実行環境とAPI利用量の制御方法。
- DBテーブル構成・保存期間。
- 現行計算とGemini予測を比較する精度評価方法。

本書の設計案は確定仕様と区別し、未確定事項を確認してから詳細設計・実装に進む。

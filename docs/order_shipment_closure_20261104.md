# 出荷管理：注残打ち切り（2026-11-04）

## 要件と利用手順

出荷管理に打ち切りボタンを追加する。在庫が0個でも未完納の受注を表示し、打ち切りを実行できる。数量入力枠の半幅と在庫上限内の自動入力は維持する。

1. 出荷する分があれば、先に通常の出荷ボタンで実際の数量を出荷する。
2. 打ち切りボタンを押す。理由入力は不要。
3. 確認画面で、残注残を完了扱いにすること、入力中の出荷数は出荷しないこと、在庫数量を減らさないこと、引当を解除すること、以後の出荷・出荷取消ができないことを確認する。
4. 出荷・注残・進捗・外注・生産予定・受注別工程の稼働一覧から非表示となる。受注・実績・ロット等のデータは物理削除しない。
5. 出荷管理の「打ち切り履歴」から日時（日本時間）・注番・得意先・製品・受注数・出荷済数・打ち切り数・操作者・理由を確認できる。新しい順、30件表示、検索あり。

## データと権限

- posts.shipment_closed_atで通常の完納・誤登録取消と区別する。
- order_shipment_closuresに打ち切り当時の情報を保存する。未出荷引当の解除明細もJSONで記録する。
- 出荷数や製造実績を水増ししない。在庫実数、仕掛残数は変更しない。未出荷の在庫引当のみ解除し、他の受注への引当は維持する。
- close_order_shipmentsは現在のログイン・有効会員をDB側で確認し、操作者を取得する。通常の出荷と同様、有効な一般ユーザーも操作できる。
- API側もrequireApiUserを使用し、入力を検証する。操作キーを再利用した通信再試行は冪等。理由が送られない場合はAPIで「理由入力なし」を補う。
- 受注をロックして最新の実出荷から残数を計算する。引当解除・履歴保存・完了フラグ更新は単一トランザクション。どれかが失敗すれば全て取り消す。
- ロック順を通常の出荷と合わせ、受注→ロット→在庫→引当とする。
- 打ち切り後の追加出荷・実績等の新規登録は既存require_active_orderトリガーを通じて拒否する。
- 打ち切り後の出荷取消は、解除済み引当が復活する不整合を防ぐため拒否する。打ち切り取消の機能は含めない。
- 履歴テーブルはRLSとSELECT権限だけを付与する。一般ユーザーがログを書き換え・削除できない。
- AIの新規予測対象から打ち切り受注を外す。過去の実績は保持し、架空の出荷・実績を作らない。
- 打ち切り履歴は今回の履歴削除対象に追加しない。既存の安全確認を満たさない詳細履歴は自動削除されない。

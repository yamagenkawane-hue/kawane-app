# 工程進捗後の在庫引当制限（2026-10-29）

## 要件・実装

- 注残管理の新規在庫引当は未着手の受注だけ許可する。1％の進捗も拒否する。端数処理で0％表示となる少量の実績も拒否する。
- 判定は受注ごとに行い、同じ製品の別受注の進捗や、製品全体の共通在庫では制限しない。
- 次のいずれかがあれば進捗ありとする。
  - 工程の完了数量が正数、外注の出し日・戻り実績日あり、または外注中・戻り済み状態。
  - 正数の生産実績あり。旧データの工程ID・予定ID経由の実績も対象。
  - 製造実績・工程移動・数量補正移動・入庫の履歴あり。
  - 最初の工程より後の工程に正数のロット残高あり。
- 予定数量・戻り予定日だけの登録では制限しない。
- 画面は「引当不可」「工程進捗あり」と表示し、ボタンを無効化する。クリック処理にもガードを設ける。
- DBの `confirm_inventory_allocation` でも進捗を再確認するため、画面表示後に実績が登録された場合も拒否する。
- 既存の引当は取り消さない。確定済み表示を継続する。

## DB

- `20261029_block_allocation_after_process_progress.sql` 適用済み。
- `order_has_process_progress` で判定を統一。画面は `v_order_allocation_eligibility` から同じ判定を取得する。
- 従来の引当処理は `confirm_inventory_allocation_unstarted_base` に保持し、ラッパーが進捗チェック後に呼び出す。一般クライアントとservice_roleによる旧処理の直接実行権限は停止する。
- マイグレーションの再適用も検証済み。

## 検証

- 合成データのインメモリーPostgreSQLで旧出荷処理の回帰55項目＋新しい引当制限49項目、計104項目成功。
- 1％、表示上の1％未満、完了済み、生産実績だけがある場合、旧予定経由、外注出し・状態、工程移動・履歴、画面表示後の進捗登録を検証。
- 未着手の引当成功・拒否時に在庫や引当が増減しないこと・既存引当の保持・旧関数への直接実行不可を確認。
- 画面・既存処理のオフライン検証86項目成功。未着手の確定ボタン、進捗ありの無効ボタンと理由、既存確定済み表示を確認。
- 型検査・ESLint・本番用ビルド成功。
- 実DBでは読み取りでガードの導入と、旧関数をanonから直接実行できないことを確認。
- ローカルブラウザー `/orders` で進捗ありの受注に「引当不可／工程進捗あり」が表示され、無効化されていることを確認。
- 実DBで合成レコードを作成する検証は自動承認レビューで停止されたため実行していない。代わりに実DBの読み取り確認と画面確認を実施。`verify_allocation_progress_20261029.sql` は未実行の検証用スクリプト。

本番DBへの制限反映は完了。公開アプリのデプロイは今回実施していない。

# 出荷管理の数量表示改善（2026-11-04）

承認済み要件：注残・出荷上限・出荷後の残数を表示し、出荷数を上限で初期表示する。入力幅は数量欄の約半分とする。

## 仕様と実装

- 受注全体の受注数、取消分を除く出荷済数、注残数を表示する。
- ロット在庫数と出荷可能在庫を区別する。出荷可能在庫は未引当在庫＋当該受注の未出荷引当数量で算出し、他受注への引当分を除く。
- 注残数とロットの出荷可能在庫の少ない方を今回の出荷上限とし、既存ビューの上限も超えない。
- 出荷数は上限を初期表示し、利用者は小さい数に変更できる。複数ロットも行ごとに登録し、注文全体の注残を共有する。
- 入力中に出荷後の注残、出荷後のロット在庫を表示する。不正数量の場合は負数の予測を表示せず、理由と具体的な数量を表示する。
- 出荷数の入力枠は50%幅、最小110px・最大140pxとし、6桁の入力を考慮する。テンキーは初回入力時に初期値を置換する。
- 登録前に再取得して数量と予定日を確認し、確認ダイアログにも出荷後残数を表示する。最終確定は既存の原子的なregister_shipmentで検証する。
- 競合409時は再取得して最新の注残・上限を案内する。読取失敗時は登録を進めない。
- 二重操作防止、既存の冪等キー、在庫減算・引当消込・出荷履歴保存は維持する。
- DB構造変更なし。業務データを変更する実出荷テストは実施しない。

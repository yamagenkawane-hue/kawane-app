APIが返した利用量:

- 入力: 204トークン
- 回答: 115トークン

現行コードは対象工程をまとめて1回のGeminiリクエストにする。通常の定期実行は1日1リクエストで、手動更新や同じGoogleプロジェクトの他用途は別途加算される。実績不足でGemini対象工程がなければ0リクエスト。

無料枠に収まるかは、対象工程数に応じた入力トークン数とプロジェクト固有のRPM・TPM・RPDの確認が必要。今回の小規模サンプルだけでは全件処理の利用量を保証できない。上限はAPIキー単位ではなくプロジェクト単位で、RPDは米国太平洋時間の午前0時にリセットされる。[公式利用制限](https://ai.google.dev/gemini-api/docs/rate-limits)

## 修正と再現方法

`lib/aiPrediction/runner.ts` の以下を修正した。

1. 90日経過時の削除対象から評価記録を除外。仕様どおり長期評価用に保持する。予測中間データ・実行履歴の90日削除は継続する。評価記録の実行IDは既存DB定義の `ON DELETE SET NULL` で処理される。
2. Gemini対象が0件ならAPIキーを要求しない。能力設定だけでの予測を可能にする。
3. Geminiの所要日数は整数のみ採用する。
4. 完了何日前の予測かは、実績確定時に予測作成日の日本時間と実際の完了日から算出する。未完了の間は未確定値として扱う。

ローカルで次を実行する。

```powershell
node scripts/verify-ai-prediction.mjs
npx tsc --noEmit
npx eslint lib/aiPrediction/runner.ts scripts/verify-ai-prediction.mjs
```

架空データによる外部API検証とDBの読み取り確認:

```powershell
node scripts/verify-ai-prediction.mjs --live
```

`--live` は環境変数の既存認証情報を使用する。DBの読み取り、Geminiへの架空データ1リクエストを実行し、キーや受注データを出力しない。利用契約に応じてAPI利用量・料金が発生し得る。

ローカル検証の対象は、休日・週末、外注の暦日、休業日の開始日補正、営業日誤差の符号、Gemini不要時の動作、評価記録の保持、能力0時の前回結果維持、実績完了日基準の予測時点評価、小数日数の拒否の9項目。DBを代替したテストなので、DB権限や実際の削除・外部キー動作の結合テストを代替しない。

初回結果: 9項目すべて成功。TypeScript型チェック、変更したコードのESLint、差分の空白チェックも成功。

## 契約・料金・データ取り扱い

2026-09-25確認時、Gemini 3.8 FlashのStandard料金は無料枠あり。有料枠は100万トークンあたり入力0.75 USD、出力（思考を含む）3.75 USDで、2026-12-31まで。2027-01-01から入力1.50 USD、出力7.50 USDと掲載されている。[公式料金](https://ai.google.dev/gemini-api/docs/pricing)

今回のサンプルを有料Standard単価で計算すると、(204×0.75 + (115+607)×3.75) / 1,000,000 = 約0.00286 USD/回。これは比較用の試算であり、実際の請求額や通常運転の費用ではない。

無料サービスでは入力・回答が製品改善に利用され、人によるレビューの対象になり得る。機密情報・個人情報を送信しない条件がある。有料サービスでは入力・回答を製品改善には使用しないが、不正利用対策等のため限定期間の記録はある。Gemini APIの有料サービス扱いは、使用プロジェクトに有効な課金アカウントが関連付けられていることが条件。[公式利用条件](https://ai.google.dev/gemini-api/terms)

現行送信内容は工程ID・工程名・数量・集計実績・外注区分で、得意先名・製品名・注番は送信項目に含まれない。ただし、数量・生産能力も社外秘であれば無料枠への送信は適さない。本番で扱うデータの区分と現在の課金状態は未確認。契約の変更は行っていない。

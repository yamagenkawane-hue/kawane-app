# 打ち切り受注の復元（2026-11-04）

## 仕様

出荷管理→打ち切り履歴で、打ち切り中の履歴に「復元」ボタンを表示する。確認画面だけで復元し、理由入力は求めない。元の打ち切り履歴を残し、状態・復元日時（日本時間）・復元操作者を表示する。復元済みの行ではボタンを表示しない。

受注の打ち切りフラグを解除し、現在の受注数と実際の出荷数から通常の注残判定へ戻す。在庫実数・実績・出荷済数量は変えない。打ち切り時に解除された引当は、その後他の受注で使われる可能性があるため自動では戻さない。この点を確認画面と完了メッセージで案内する。必要な場合は既存の引当・通常出荷を利用する。

## DBとAPI

- order_shipment_closuresにrestored_at/restored_actor_id/restored_actor_name/restore_request_idを追加する。
- 受注ごと1件の制約を「未復元の打ち切りは受注ごと1件」の部分一意索引へ変更し、復元後の再打ち切りを別の履歴として保存できるようにする。
- restore_order_shipmentsは有効会員と実際の操作者をDBで確認する。対象受注をロックし、履歴との状態一致・取消済みでないこと・注残が残ることを確認する。
- 履歴の復元情報と受注フラグを一括更新する。失敗時は両方ロールバックする。
- 同じ処理キーによる再送は冪等。古い復元要求の再送で、後から作られた新しい打ち切りを解除しない。
- 既存のRLS・直接更新禁止を維持。復元情報のある履歴に対応する場合だけ完了フラグの解除を許可する。
- PATCH /api/shipment-closuresで操作。GETで復元情報も返す。通常の打ち切りと同じ有効なログインユーザー権限を使う。

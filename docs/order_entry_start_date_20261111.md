# 受注登録・生産予定の開始予定日（2026-11-11）

## 要件・設計

- 受注登録のロットNo入力を、任意の開始予定日（日付入力）へ変更する。
- 項目順は「注番・開始予定日・得意先名・製品名・製品コード・受注数量…」。
- 得意先は得意先IDで選択し、該当得意先の製品のみ表示する。製品は製品IDで選択し、製品コードは自動入力・編集不可。
- 得意先を変更したら製品選択をリセットする。同名製品は製品コードを併記して区別する。
- 生産予定のロット列・検索欄を開始予定日に変更する。製造G・品質管理G・梱包出荷G・全体表示に適用する。
- 生産予定の新しい日付セルは、旧ロットセルと同様に表示専用。受注登録で入力した日付を表示・検索する。
- 実際のロットNoは既存列に保持し、開始予定日への変換・上書きを行わない。

## 実装

- posts / production_schedules に nullable date型の planned_start_date を追加する。
- 受注・生産予定の既存ビューの列順を保持し、末尾に開始予定日を追加する。security_invokerと既存権限を維持する。
- 受注に開始予定日があれば生産予定ビューで優先し、それ以外は生産予定自身の開始予定日を使う。
- 旧受注の日付は未設定のまま保持する。開始予定日は完了予定日・納期以前であることを画面・DB双方で検証する。
- 得意先・製品マスタは全件取得する。旧データで得意先IDがない製品は、得意先名が一意な場合だけ名称照合を許可する。
- 保存時も得意先に属する製品IDであることを再確認し、画面操作による別得意先の製品混入を防ぐ。
- 受注登録の完了予定日計算は従来同様、納期から得意先の出荷調整日数を暦日で引く。得意先変更時も再計算する。
- AI予測は「受注の開始予定日 → 生産予定の開始予定日 → 従来の予定開始情報」の順で参照する。Geminiの実行・本番予測更新は本作業では行わない。
- 既存の退避ファイルとの互換性のため、開始予定日がNULLなら履歴パケットへ新規キーを含めない。非NULLならキーを含め、従来のダイジェスト・基本情報一致検証の対象にする。

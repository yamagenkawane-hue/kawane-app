# 注残管理の開始予定とデイリー表示条件

## 確定仕様

- 注残管理の「状態」の右隣に「開始予定」を追加する。
- 編集・保存で受注の `posts.planned_start_date` を変更できる。
- 受注登録済みの開始予定日も同じ項目に表示する。
- 未入力の受注はデイリー生産予定に表示しない（ユーザー確認済み）。
- 開始予定日が日本時間の今日以前の受注を、既存の注残・工程条件に従って表示する。
- 未来日・未入力の受注は、保存済み予定やロット工程残があっても全ての部署から除外する。
- 納期超過や旧出荷予定の期間を理由として、開始前の受注を表示しない。
- 開始予定を空欄で保存すると NULL に戻り、デイリーの対象から外れる。
- 不正な日付、完了予定日・納期より後の開始予定日は保存しない。

## 設計・変更範囲

既存の日付列と受注表示ビューを利用するため、SQL適用・既存データの一括更新は不要。
開始予定日の正本は受注とし、古い生産予定側の開始予定日を表示へ戻さない。
APIの抽出条件とクライアントの各部署表示の双方に開始予定日判定を適用する。
ロット工程表示は受注IDで照合し、ID付き生産予定を別受注の同じ注番で復活させない。
出荷取消フラグ NULL は有効な出荷として扱い、従来の出荷管理の集計とそろえる。

# 出荷可能在庫を出荷してから注残完了（2026-11-04）

## 承認された動作

受注100個・未出荷・出荷可能在庫60個なら、60個を実際に出荷して在庫を減らし、出荷済合計60個で注残を打ち切り完了とする。未出荷40個は、実際に出荷した数量と区別して記録する。「40個で打ち切り」という表示にはしない。

- 打ち切りボタンの確認画面に今回出荷予定・出荷済合計・未出荷終了予定を表示する。
- 数量入力欄の値ではなく、確定時の注残と出荷可能在庫から計算する。
- 同じ製品の複数ロットがある場合は、ロットID順で合計して出荷する。他の受注の引当は使わず、当該受注の引当と未引当在庫だけを使う。
- 在庫が足りれば通常の完納とする。余剰在庫は残す。在庫0なら出荷せず、その時点の出荷済合計で注残を完了にする。
- 出荷と在庫減算は既存register_shipmentを利用し、実出荷・引当消込・ロット数量・在庫移動明細を正しく残す。
- 未出荷が残る場合は既存close_order_shipmentsで完了フラグと監査履歴を記録する。
- 履歴は「打ち切り時出荷済合計」「未出荷数」に分け、状態に「60個で打ち切り」等を表示する。以前の打ち切り記録も同じ意味の数量として表示する。
- 理由入力は不要。理由は「理由入力なし」で記録する。

## 整合性・権限

ship_stock_and_close_orderで全てを単一トランザクションにまとめる。途中で失敗すれば、出荷・在庫減算・打ち切り・処理記録を全てロールバックする。実行時に会員・操作者を確認し、受注→ロット→在庫の順でロックして通常出荷と整合させる。

app_private.shipment_cutoff_requestsに処理キー・受注・操作者・予定日・結果を保存する。出荷だけで全数完納した場合も再送で重複出荷しない。再送した入力や受注が違う場合は拒否する。復元後に古い要求が再送されても再出荷・再打ち切りしない。

旧close_order_shipmentsは内部処理として残し、authenticatedの直接実行権限を外す。APIは新しい一括関数を呼ぶ。個別の復元機能は維持する。復元しても、今回の実出荷・在庫減算までは取り消さない。必要な出荷取消は復元後に既存の管理者用取消を使う。

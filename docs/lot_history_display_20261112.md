# 注番・ロット履歴の梱包日と工程順

## 要件・設計・実装

- 梱包日は対象ロット自身の正の梱包実績から最新の実績日を取得して表示する。実績日が取得できないときは登録済みの`lots.packaged_at`を使用し、どちらもなければ「-」。更新日時や他ロット・受注全体の完了日から推測しない。DBの業務日付は変更しない。
- 製品工程マスタの工程順を優先する。受注工程と製品工程をIDで対応付け、同じ名前の工程が複数ある場合も識別する。マスタ変更・削除・旧データで対応しない場合は受注に保存された工程順を使用する。
- 各工程の実績と対応する工程移動をまとめ、上から工程順の逆順に表示。同一工程内は実日付の新しい順、同じ日の工程移動は実績の直上に表示する。処理IDで安定した順序を維持する。
- ご指定の例は下から「製造→工程移動→洗浄→工程移動→検査→工程移動→計量→工程移動→梱包→工程移動→出荷→在庫登録」。出荷・在庫登録は工程の上に配置し、在庫登録を最上段にする。各行の日付自体は変えない。
- 外注日程・分割日程も該当工程へ配置する。履歴は30件表示を維持し、取得は全件ページングとして1,000件超の梱包実績等の欠落を避ける。

変更：`app/lots/[id]/page.tsx`、`lib/lotHistoryOrder.ts`。

## 検証

`verify-lot-history-order.mjs`でスクリーンショット相当の12行、同日実績と移動の混在、マスタ順と旧受注順の相違、同名工程、複数日の梱包、不正日付、梱包日不明、他ロットの表示状態を検証（17確認）。`verify-product-lot-ui.mjs`でロットIDによる履歴の分離を回帰確認（18確認）。いずれも成功。型検査・Lint・本番ビルドも成功。

本番の対象ロット`20261109-1-A-1`を読取確認した結果、`packaged_at`はNULLだが当該ロットの梱包実績日は2026-11-12だった。修正後はこの実績日を表示する。製品工程マスタも製造1・洗浄2・検査3・計量4・梱包5であることを確認した。

DB変更は不要。実績・在庫・出荷の登録や取消の試験は本番では行わない。

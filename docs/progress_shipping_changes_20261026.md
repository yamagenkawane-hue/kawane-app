# 進捗・出荷・誤登録取消の変更（2026-10-26）

## 要件と実装

- 削除は未着手の誤登録・重複登録の取消専用。ボタンを「誤登録取消」とし、在庫は減算しない。
- ロット、実績、引当、工程移動、出荷履歴がある注番は取消不可。取消済み出荷履歴や旧形式の注番参照も保護する。未着手の工程・予定は削除せず保持する。
- DBの更新トリガーでも取消条件を確認する。アプリからの注番の物理削除権限を除き、一括取消も同じRPCを使用する。
- 出荷は選択したロットから減算。出荷履歴の作成・在庫・引当・ロット集計の更新は1トランザクション。
- 注残は `受注数 − 有効な出荷数`。梱包完了や在庫引当では減らさない。全数出荷後は注残・進捗一覧から除外し、注番・実績・出荷履歴は残す。分納は残数を表示する。
- 出荷取消では、新規出荷に保存した在庫・引当の移動明細をそのまま復元する。二重取消は再加算しない。既存の出荷履歴は既存の取消処理を維持する。
- 他の注番の引当を消費しない。注残超過・在庫不足・別製品のロットを拒否する。処理キーで再送を重複登録せず、ブラウザーでも実行中の再押下を防止する。
- 進捗は得意先昇順、全件表示。検索欄はトップページへ戻るボタンの右隣へ拡大配置。
- 工程の日付列と引当数列を非表示。移動済み・残高ゼロのロットを元工程に表示しない。履歴・作業日は保持する。
- 計量の「完了」で計量・梱包実績を指定した作業日に記録し、梱包在庫へ入庫する。既存の梱包待ちも計量欄から完了可能。後続工程がある異なる構成や同ロットの既存梱包待ちがある場合は処理を止める。
- 梱包在庫は現在の製品在庫数。在庫合計は製造～計量・梱包待ちの現在数量＋梱包在庫。製品単位の在庫を注番ごとに重複加算しない。
- 進捗の残数は `在庫合計 − 未出荷の受注数量合計`（負数は不足）。数量補正の累計は補助表示し、現物在庫に足し戻さない。
- 数量編集・工程移動時の理由入力を省略し、固定の操作説明と変更数量を履歴に残す。
- 全件表示の裏側も1,000件ごとの安定したID順で取得し、先頭1,000件への欠落を防ぐ。

## 反映手順と留意点

1. 本番スキーマとの差分と既存在庫のロット紐づけを確認する。既存の在庫・引当の不整合をこの変更で推測して書き換えない。
2. `20261026_safe_shipping_and_order_cancellation.sql` と `20261026_progress_completion.sql` を適用する。前提は既存の出荷取消RPC・20261020の作業日対応済み工程移動RPC。
3. アプリを同じ作業時間帯に反映する。DB変更で旧在庫減算RPCの一般クライアント実行権限を停止するため、旧アプリでの出荷を続けない。
4. 進捗・注残・出荷画面の読み取り確認を行う。実取引による出荷試験は業務上の対象・数量を決めて実施する。

新出荷はロットIDに紐づく在庫を対象とする。ロットIDのない旧在庫を自動で別ロットへ紐づけない。旧履歴の在庫減算方法が不明な場合は従来の取消処理が使われるため、旧データの正しさまで保証するものではない。

アプリだけを旧版に戻して旧減算RPCを再開するロールバックは、新しい移動明細との整合を崩すため行わない。出荷を停止して原因を確認する。CSV保留・AI予測の手動更新ボタンは今回の対象外で、変更していない。

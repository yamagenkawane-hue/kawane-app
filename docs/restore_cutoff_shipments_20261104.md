# 打ち切り時に出荷した分の在庫復元（2026-11-04）

## 確定した要件

通常出荷50個、その後に打ち切り操作で30個を出荷した受注を復元する場合、打ち切り時の30個だけを取り消し、在庫へ戻す。以前の通常出荷50個は出荷済みのまま保持する。

## 実装

restore_order_shipmentsを更新する。元の打ち切り履歴に対応するapp_private.shipment_cutoff_requestsと出荷の冪等キーで、打ち切り操作が作成した出荷のみを識別する。出荷・移動明細の数量一致を確認し、元の在庫・元の引当・ロット数量へ逆の移動を適用する。対象出荷は物理削除せず、取消日時と「打ち切り復元（履歴ID）」を残す。

通常出荷・別受注の出荷・別の打ち切り操作の出荷は取り消さない。出荷を伴わなかった旧形式の打ち切りは、従来どおり注残状態だけを戻す。既に復元済みの記録を遡及的に変更しない。

履歴にrestored_shipment_quantityとrestored_shipment_idsを追加し、戻した在庫数量と出荷IDを記録する。画面に在庫復元数を表示し、確認画面でも「打ち切り時の出荷だけを取り消す」と案内する。打ち切り時に別途解除した引当は従来どおり自動再引当しない。

完了フラグ解除、履歴の復元日時・操作者、対象出荷取消、在庫・引当・ロット数量の復元は単一トランザクションで行う。途中で失敗すれば全てロールバックする。元の在庫・引当・ロットがない場合や数量明細が一致しない場合は復元しない。既存の会員確認・冪等処理・履歴改ざん防止を維持する。

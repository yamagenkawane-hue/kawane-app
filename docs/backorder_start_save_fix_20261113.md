# 開始予定が保存できない問題の修正

## 原因

注残管理の既存保存処理が、表示用の `remaining_amount` を `posts` の更新へ送信していた。
本番の `information_schema.columns` を読み取り、この列が `posts` に存在しないことを確認。
開始予定日を含めた受注更新全体が、存在しない列への更新として失敗する。
`planned_start_date` 自体の存在と authenticated の更新権限も確認済み。

## 修正

受注更新から `remaining_amount` を除外。注残数は従来どおり受注数と有効出荷数から計算する。
開始予定日の保存、空欄での解除、日付の入力チェック、デイリーへの表示条件は維持。
DB変更や既存受注の書き換えは行わない。

## 検証改善

テスト用DBが任意の列を受け入れていたため、前回の検証で保存不良を検知できなかった。
実スキーマで確認した更新列だけを許可し、不明な列は PGRST204 として拒否するモックへ変更。
開始予定日の変更・再取得と空欄保存を確認し、注残数を更新しないことを検証する。
本番ではスキーマ・権限の読み取りだけを行い、受注を変更する試験は行わない。

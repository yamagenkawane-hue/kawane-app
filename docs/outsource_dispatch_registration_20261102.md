# 進捗管理の外注日程登録（2026-11-02）

## 変更仕様

- 初回・残数分の日程とも出し日を必須とし、予定日と戻り日（実績日）は任意。
- 出し日のみ、または出し日＋予定日の登録は、日程のみ保存する。工程残高・実績・次工程数量は変更しない。
- 戻り日を入力して「登録」を押した場合のみ、戻り日を作業日として実績を記録し、入力数量を次工程へ移動する。予定日なしでも可能。
- ダイアログの見出しを「外注日程を登録」（残数分は「残数分の外注日程を登録」）、ボタンを「登録」に統一。
- 登録済み日付は引き継いで読取専用とし、他画面で変更された日付を上書きしない。
- 外注工程では、日程が全て入力済みでも同じ登録ダイアログを開く。

## DB処理

新しいRPC register_outsource_progressで、保存のみ／保存と移動をサーバー側で判定する。ログイン・有効会員を確認し、有効な注番・ロット、外注区分、ロック、残数量、日付を検証。登録と移動は一括処理し、エラーは全体ロールバック。旧RPCは互換用に維持する。
残数分は既存日程テーブルを使用。新規日程IDをリクエストキーから固定し、保存の再試行で重複作成しない。移動済みの同一キーは二重計上しない。既存の分割数量と初回日程を保持し、分割移動後の未移動残数を残す。

## 検証

- 隔離DBの旧25項目＋新66項目、合計91項目を確認。出し日のみ、予定日追加、戻り日登録、数量、再実行、ロック、不正日付、分割外注、連続する外注工程、権限、失敗時ロールバックを含む。
- UI回帰155項目、型チェック、ESLint、本番ビルドを確認。
- 本番DBへ追加関数を適用。匿名実行不可とsearch_path固定を読取確認。追加のSECURITY DEFINER診断は、関数内で有効会員を検証する意図的な業務RPCとして確認。
- ローカル画面ではJS1011のロットでダイアログを開き、出し日のみで入力validityが通ることと登録ボタンを確認。業務データへの保存は行わずキャンセルした。

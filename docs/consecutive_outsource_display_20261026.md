# 連続外注工程の進捗表示修正（2026-10-26）

## 変更

- 表示欄を工程番号の固定値で判定せず、工程マスターの種類・工程名・外注区分で決定する。
- 同じ残高を複数の工程欄へ表示しない。外注は「洗浄・外注」、検査は「検査」、計量と梱包待ちは「計量」に一度だけ表示する。
- 工程番号が5以降でも、外注や検査のボタンは「次工程へ移動」。内部の計量・梱包だけ「完了」とする。
- 工程番号に欠番があっても、注番に登録された全工程の実際の並び順と工程数を使って進捗率を算出する。完了在庫は100%。標準5工程の表示は従来の0/20/40/60/80%と同じ。
- 進捗一覧の行と製品グループ集計で、共通の判定・進捗率関数を使用する。
- 工程マスターの分類と、各注番の工程数・順番を読み取り時に付与する。DBのスキーマ・業務データの変更は不要。

## 検証

- 画面・ヘルパー・既存APIのオフライン検証58項目成功。
- 「製造 → 外注A → 外注B → 外注C → 検査 → 計量 → 梱包」の表示を検証。各ロットの表示は1回、検査と外注の重複なし、完了ボタンは計量・梱包の2箇所だけ。
- マスター外注区分で判定する、名称に「外注」「メッキ」を含まない工程も検証。8番目の外注工程も完了扱いにならない。
- 全7工程の場合、検査57%、計量71%、梱包待ち86%、完了在庫100%を確認。
- 連続外注のDB検証をテストスクリプトへ保存。外注AとBの日程が別々に保持され、Bから検査へ数量が移動することを含む25項目成功。インメモリー検証であり実DBデータの変更なし。

## 対象ファイル

- `lib/progressProcess.ts`: 単一の表示欄・完了判定・工程メタデータ・進捗率計算。
- `app/utills/useFetchPosts.tsx`: マスター分類と注番の工程構成を付与。
- `app/components/ReservationList/ReservationList.tsx` / `app/reservation/page.tsx`: 共通判定を利用。
- `app/components/TableHeader/TableHeader.tsx`: 「洗浄・外注」見出し。
- `app/type.ts`: 表示分類と工程構成の任意フィールド。

# 誤登録取消の本人確認と履歴保存

## 要件・設計

注残管理一覧の誤登録取消には、現在ログインしている管理者のパスワード入力を必須とする。別管理者のIDやパスワードによる代理実行は認めない。既存の「実績・ロット・引当・出荷等のある注番は取消不可」を維持する。成功した取消の日時、注番、得意先、製品、受注数、操作者を履歴に保存する。

UIのパスワードは伏字で表示し、サーバーの認証済みIDからAuth内部IDを選んで照合する。本文中の操作者ID・メールは使用しない。確認用の一時セッションはlocal指定で終了し、元のログインを維持する。確認は15分あたり15回まで。パスワードは履歴・ログ・localStorage等へ保存しない。

削除はサーバー専用RPCへ集約する。既存のパスワード不要RPCのanon/authenticated実行権限を廃止し、他画面からの迂回も防ぐ。DB側でも操作者の有効管理者区分と元のAuthセッションを再確認する。削除フラグ更新と履歴保存を同一トランザクションにし、どちらかが失敗すれば全体を戻す。

## 実装

- `pages/api/order-cancellations.ts`：管理者限定GET/POST。本人のパスワード照合、試行制限、確認用セッションの破棄、本文IDの偽装防止、DBエラーの制御。
- `app/components/OrderCancellation/`：共通のパスワード確認ダイアログ。未入力禁止、二重押下防止、エラー時のパスワード消去、同じ処理キーでの再試行。
- `app/orders/page.tsx`：誤登録取消を確認ダイアログへ接続し、「誤登録取消履歴」のリンクを追加。
- `app/orders/history/page.tsx`：新しい日時順、検索、1ページ30件の履歴。管理者だけが表示・取得可能。
- 進捗管理・旧予約画面の削除導線も共通化。複数取消は1回の確認で一括処理し、途中失敗では全件戻す。
- `20261112090001_secure_order_cancellation_audit.sql`：履歴テーブル、管理者限定SELECTのRLS、サーバー限定取消関数、旧RPCの直接実行拒否。

履歴は注文・ユーザーから独立したスナップショットとして保持する。後日の名称変更や元業務データの保管期限による削除でも当時の情報を失わない。新しい履歴は既存の業務履歴削除処理には含めず、今回の機能追加後に行う取消から記録する。過去の操作者・取消日時が不明なデータは推測で補完しない。復元機能の追加は今回の対象外。

## 検証

- API：未ログイン・一般利用者・未入力・誤パスワード・別人の照合結果・回数超過・認証障害を拒否。元の管理者IDとセッションを使用し、パスワードをDB関数へ渡さない。確認用セッションだけを終了する。42確認。
- DB：本人の有効管理者・セッション検査、既存の着手済み拒否、複数取消の全体巻戻し、履歴失敗時の巻戻し、再送時の重複防止、旧RPCの直接実行拒否、一般利用者の履歴非表示、履歴改変拒否。23確認。
- UI：伏字入力、空入力禁止、失敗時の消去、再送キーの保持、二重押下防止、キャンセル、履歴30件表示・検索。23確認。
- 型検査・Lint（警告0）・本番ビルドが成功。回帰テスト32スイートがすべて成功。結果は`order_cancellation_verification_20261112.json`へ保存。

これらは合成データとオフライン画面イベントの検証。本番の受注は取り消さず、本番管理者のパスワードも取得しない。

# 打ち切り履歴の数量表示（2026-11-04）

## 表示

- 受注数：注番に紐づく現在の受注データ（posts.order_amount）から取得する。
- 出荷済み数量：同じ受注の現在有効な出荷の合計。取消済みの出荷を除く。旧形式のpost_idがない履歴は注番で関連付ける。
- 直近の出荷数：その打ち切り操作で実際に出荷した数量。複数ロットはその操作分を合計する。打ち切りの復元で出荷が取消済みになっても、当時の出荷数として保持して表示する。
- 例：100個受注、通常分納50個、打ち切り時49個出荷なら、受注数100・出荷済み数量99・直近の出荷数49。
- 理由列と状態列を削除する。復元日時・操作者・在庫復元数と、未復元の行の復元ボタンは維持する。

## 実装

GET /api/shipment-closuresで受注・出荷を並列で全件取得し、lib/shipmentHistoryQuantities.tsで表示用数量を集計する。DBに保存した打ち切り当時の監査数量は上書きしない。復元後は履歴を再取得し、取消を反映した出荷合計を表示する。再取得失敗時でも復元済み状態を画面に反映し、再読込を案内する。

DB構造・関数変更なし。業務データを変更する試験は実施しない。

## 検証

- 数量集計18件：100・50+49=99・直近49、取消、複数ロット、別受注、複数の打ち切り、旧形式出荷。
- API37件：受注元数量100・出荷合計99・打ち切り時49の応答を含む。
- 復元UI26件：100/99/49の描画、理由/状態列なし、復元後の出荷合計再読込、ボタンと30件ページング。
- 一般ユーザーの本番DB読取・権限検証22件成功（ローカルAPI、業務データ書込なし）。
